# Computer MCP 1.0.1

[简体中文](https://github.com/Sanjeever/computer-mcp/blob/v1.0.1/docs/releases/1.0.1.zh-CN.md)

## Changes

- Windows now returns `stale_snapshot` when UI Automation still resolves a control whose native window handle has been destroyed. Observe the target again before attempting another action.
- Windows desktop tests now check that window and screen captures reflect current content, including a dedicated WPF fixture. They also cover pointer coordinates on cropped and scaled images, rejection at a covered point, and follow-up screenshots after drawing.

## Upgrade

Update any pinned npm version to `@sanjeever/computer-mcp@1.0.1` and restart the MCP client. [Setup guide](https://github.com/Sanjeever/computer-mcp/blob/v1.0.1/README.md)

## Verification

In a Windows 10 x64 VM with one display at 100% scaling, locally built tarballs passed offline installation and the launcher passed the stdio smoke test. Capture, drawing, dialog, menu, and owned-popup fixtures passed twice using the installed native server. The full fixture suite still intermittently reports a missing mouse modifier state. The same behavior was reproduced with the 1.0.0 code.

The tagged [Release workflow](https://github.com/Sanjeever/computer-mcp/actions/workflows/release.yml) records build and install checks for the published artifacts.
